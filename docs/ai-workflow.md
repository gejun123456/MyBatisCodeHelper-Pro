# 用 AI 修改 MyBatis：从需求到验证

已经在用 AI 写代码，可以把插件接入现有工作流：让 AI 查询当前项目的 Mapper、数据库元数据和生成配置，修改后调用检查与 SQL 求值工具，减少手动整理上下文、重复描述和反复排错的操作。首次使用请先完成 [安装与接入](quickstart.md)。

以下是可复制到自己项目中的任务示例，不是性能对比或成功率承诺。请将接口名、表名和业务条件替换为实际内容。

## 场景一：给已有查询增加条件

适合接手老项目、修改动态 SQL，或同时需要调整接口参数和 XML 的任务。

```text
使用 mybatis MCP，为 com.example.mapper.OrderMapper 的现有列表查询
增加可选的下单时间范围。先查接口对应 XML、现有参数和真实表字段。
确认时间字段与类型，按项目风格修改，保留原有排序和返回类型。

修改后校验 Mapper 契约；分别用未传范围、只传开始时间、只传结束时间、
同时传入起止时间的参数渲染 SQL（execute=false）。
列出实际覆盖的条件分支和 checksSkipped。
需要验证查询结果时，使用开发 / 测试数据和明确断言运行测试。
最后汇报改动、实际执行的验证及剩余问题。
```

| 阶段 | 插件提供的信息或操作 | 应检查的结果 |
| --- | --- | --- |
| 找到原有实现 | `find_mapper_xml`、`list_mapper_statements` | 改的是已有接口对应的语句 |
| 确认字段 | `get_table_columns` | 字段名、类型与当前数据源一致 |
| 修改后检查 | `validate_mybatis_mapper` | 参数、属性与映射检查结果；哪些检查未执行 |
| 检查动态条件 | `run_mybatis_sql` | 指定参数下渲染的 SQL、条件求值和语法结果 |
| 验证业务行为 | `generate_mapper_testcase`，再补充并运行测试 | 有效输入、预期结果断言、实际执行结果 |

## 场景二：按项目现有规范生成 Mapper

适合新表接入已有工程，避免每次向 AI 重复说明目录、包名和生成风格。

```text
使用 mybatis MCP，为开发库的 orders 表生成 MyBatis 代码。
先列出数据源与表，确认目标 schema，读取真实列信息和项目 generator profile。
参考项目中已有 Mapper 确定模块、目录、包名和代码风格。
如果配置不完整，先列出需要确认的内容，再生成；不要猜测目标目录。
生成后检查变更，运行 Mapper 静态校验，并报告生成文件与未执行的检查。
```

`generate_crud` 会写入项目文件。生成前明确目标模块与目录，生成后查看差异。增量合并依赖生成标记等条件，见 [代码合并规则](databaseToCrud.md#代码是如何自动合并的)。

## 场景三：定位 AI 写出的 Mapper 为什么不能运行

```text
使用 mybatis MCP，检查 com.example.mapper.UserMapper。
先校验接口和 XML 契约，结合错误行号定位参数绑定、属性映射或语法问题。
如果涉及动态 SQL，使用能复现问题的实际参数，先以 execute=false 渲染。
缺少数据源或参数时说明缺失项，不要猜测验证结果。
修复后重复相关检查；如运行测试，报告命令、结果与断言。
```

静态检查可以帮助定位语法、引用和映射问题；结果是否满足业务需求，仍需要有预期结果的测试。一次渲染只覆盖指定输入，不代表所有动态分支均已验证。

## 如何比较时间与 Token 消耗

选一个你最近实际做过的小任务，用相同项目起点、需求、模型和完成标准，分别尝试现有 AI 工作流和接入插件后的工作流。两次都应检查最终代码与验证结果，再记录：

| 指标 | 记录什么 |
| --- | --- |
| 完成耗时 | 从提出任务到完成相同验证的时间，包含配置、人工操作和纠错 |
| 人工介入 | 复制表结构、寻找 XML、解释目录与纠正生成结果的次数 |
| Token 与费用 | 客户端报告的输入、输出及可见的缓存用量；按量计费时记录实际调用费用 |
| 完成质量 | 最终差异、已执行与跳过的检查、实际测试和断言结果 |

把 MCP 工具定义、调用和返回内容一并计入 Token 消耗。首次接入成本与后续任务成本可分别记录；缓存和重试也会影响结果。若客户端没有完整用量数据，先比较耗时和人工介入，不估算节省比例。

按量计费时，Token 减少有机会降低实际调用费用；固定订阅下，Token 减少不一定降低月费，但可以减少额度消耗。可将订阅插件的费用与同一周期内实际节省的开发时间、AI 费用一起比较，再判断是否值得购买。
